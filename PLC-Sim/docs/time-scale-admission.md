# 仿真倍率准入

公共 `SimulationClock` 只接受有限正倍率；构造或赋值遇到 NaN/Inf、零和负数时抛出
ValueError。赋值失败保留原倍率与时间锚点，原有连续变速计算不变。

SZLab CLI 在构造通信适配器前验证倍率；PTLC 的 `serve` 在构造适配器之前验证
原有 `(0,1000]` 范围。此前 PTLC 在连接、检查节点和初始化之后才拒绝非法倍率，
现非法配置直接返回 2，不连接、不初始化或清理协议变量。CLI 优先于现有配置文件；
不可转为浮点值的配置也以 2 退出。PTLC 的 `list/check` 不使用倍率，保持原行为。

41 项准入检查覆盖配置、CLI 覆盖、非法赋值保持时间连续及有效范围；原实现复现 21 项失败。
与已有包运行时、CLI 和两设备握手回归合计 129 项通过，1 项可选 Catalog 环境检查跳过。
测试在适配器构造处截断，不连接任何 OPC UA 端点。详细来源见
[迁移记录](../migration/clock-admission.json)。

此修复不统一各运行循环的时间，不增加暂停/单步/epoch，不把计时到期转换成物理反馈。
现有部署 JSON、OS 解析及设备定义保持。真正的 PLC 与 Isaac 步进和完成确认仍待后续接入。
