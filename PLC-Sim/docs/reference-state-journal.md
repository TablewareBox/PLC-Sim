# CPU参考状态日志

`ReferenceStateJournal(db, create=False)`集中维护原生板参考设施的状态、事件、请求及相关账本摘要。它使用调用方提供的SQLite连接；不持有设备、世界或时钟，不创建网络，不提交/回滚事务，不进行模型还原。`create=True`仅在新库中逐条建立原有meta/events/requests/commits表，已存在的表明确报错，不升级历史库。

- `save(encoded_state, time_s=..., events=..., requests=..., checkpoints=...)`保存设备包编码后的状态，并追加完整序列中的新事件/请求，返回两项数量。已有序列前缀必须保持不变；模块不逐次重算旧前缀。事务失败后下次从数据库获取数量，不保留已回滚的内存游标。
- `load(checkpoints=...)`核对状态SHA、调用方提供的当前授权/预约账本摘要及记录数量，返回独立的`CommittedState(state, events, requests, time_s)`。只读取当前连接可见状态；宿主须先回滚失败事务，不能把自己的未提交状态称为持久恢复点。

`checkpoints`以`authority`、`sample`等内部名称传入已脱敏账本快照，沿用`<name>_checkpoint`及`<name>_checkpoint_sha256`字段。调用方负责准确列出当前启用的所有账本；传空不等于已经核验授权或预约。设备具体状态由仪器包capture/restore处理，宿主仍须核对来源/模型/schema、持有单写者与世界锁，并把设备效果、操作身份、账本和save放在同一个数据库事务里。模块不能单独证明崩溃后控制器已停稳，不能用于生产授权认证。

旧四张表、canonical JSON、状态摘要和commit记录字段均保持；四种授权/预约组合、三轮保存共12次，与冻结e30255f原方法生成的全部记录逐项相同。载入增加前置数量检查，缺记录时不先调用模型还原；save明确拒绝截短的完整序列或数量不一致的新增记录。没有新的数据库schema或启动配置。

34项日志/编码检查通过。C32ar外部冻结设施已消费正式设备事实入口；在这个已通过55项的基线上仅替换保存/载入两个方法后，55项授权/预约/恢复检查再次通过，包含独立临时子进程崩溃。模块包名和源码目录两种导入均可使用纯标准库。具体命令、摘要、比较脚本与初始源码见[迁移清单](../migration/reference-state-journal.json)。

当前正式Testbed设施尚未启用世界恢复，此模块没有自动替换其操作门控、安装几何guard或改变服务。设备还原本身的中途失败仍由宿主隔离/处理；日志核验成功不能代替安全的模型发布。未改现有启动JSON、顶层simulation、OS解析；没有构建、运行ROS/GPU、接触硬件或切换现有服务。
